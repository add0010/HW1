## 1 任务选择与实现范围

实验 1A 需要接入 Npcap/libpcap 等抓包接口并解析网络数据包；实验 1B 需要设计安全文件传输协议。考虑到 Python 标准库已提供 TLS、TCP Socket 和文件操作，1B 在本机 Windows 上更容易部署和演示，因此本项目选择 1B。

实现包括带桌面界面的客户端、命令行客户端和并发服务端。用户可在图形界面中登录、浏览远端文件、通过文件选择窗口上传本地文件、下载远端文件、刷新列表并检查长连接。服务端支持多用户并发、用户目录隔离、完整文件传输、认证失败限速、文件大小及存储配额限制。演示使用双向 TLS 证书认证和账号密码认证。

```text

┌──────────────────────────┐     ┌──────────────────────────┐
│ client_gui.py             │     │ client.py（可选命令行）  │

└────────────┬─────────────┘     └─────────────┬────────────┘
             └───────────────┬─────────────────┘

                  ┌──────────────────────┐
                  │ protocol.py          │
                  │ 分帧、精确读写、摘要 │
                  └──────────┬───────────┘
                             │ 双向 TLS TCP 长连接
                             v
                  ┌──────────────────────┐
                  │ server.py            │
                  │ 并发处理、认证、配额 │
                  └───────┬────────┬─────┘
                          v        v
                      users.json  storage/<用户名>/
```

界面网络操作放在后台线程执行，并把进度和结果交回界面线程，因此大文件传输时窗口仍可响应。一个用户会话在登录后复用同一条 TLS TCP 连接；上传、下载、列表、连接测试和退出均使用该长连接。

## 3 应用层协议

### 3.1 帧格式与字段说明

TCP 提供有序字节流，但不保留应用消息边界。本协议用固定 4 字节网络字节序长度前缀标出后续 JSON 控制头长度；需要传文件时，再按控制头中的 `size` 精确收发二进制载荷。

```text
┌─────────────────────────────┬────────────────────────────────────┬─────────────────────┐
│ 长度前缀：4 字节无符号整数  │ UTF-8 JSON 控制头，最多 64 KiB     │ 可选二进制文件载荷  │
│ 网络字节序（大端）          │ JSON 长度由前一个字段给出           │ 恰好 size 字节      │
└─────────────────────────────┴────────────────────────────────────┴─────────────────────┘
```

| 字段 | 位置/类型 | 作用与校验 |
|---|---|---|
| frame_length | 4 字节，大端无符号整数 | 表示 JSON 控制头的字节数；必须为 1 至 65,536 |
| op | JSON 字符串 | 操作类型：auth、list、upload、download、ping、quit |
| name | JSON 字符串 | 单个文件名；拒绝路径分隔符、系统保留名及危险字符 |
| size | JSON 非负整数 | 文件载荷的精确长度；不得大于 512 MiB |
| sha256 | 64 位小写十六进制字符串 | 上传前约定摘要；接收端逐块计算并比较 |
| cursor | JSON 字符串或空 | 文件列表分页游标，每页最多 50 项 |

文件内容不放入 JSON，减少额外编码和内存占用。上传和下载均分块处理；接收端只有在字节数及 SHA-256 均匹配后才原子替换目标文件。TLS 保护控制头和文件内容。

### 3.2 连接、双向证书与账号认证时序

```text
客户端界面                    TLS/TCP                  服务端
   |---- TCP connect ----------------------------------->|
   |<--- ServerHello + 服务端证书 -----------------------|
   |---- 客户端证书 ------------------------------------->|
   | 客户端检查 CA 链、主机名；服务端检查客户端证书链    |
   |<================ TLS 1.2+ 握手完成 ================>|
   |---- auth(username, password)（仅在加密通道内） ---->|
   |<--- authenticated / 通用认证失败 --------------------|
   |             登录成功后连接持续保持                  |
```

演示脚本创建本地演示 CA，并签发服务端证书和客户端证书。客户端验证服务端证书链和主机名；服务端通过 `CERT_REQUIRED` 验证客户端证书。TLS 握手成功后，服务端还会独立验证账号密码。密码数据库仅保存随机盐和 PBKDF2-HMAC-SHA256 派生值。

### 3.3 列表、长连接与退出时序

```text
客户端                                             服务端
   |---- list(cursor?) ----------------------------->|
   |<--- 文件名、大小、next_cursor ------------------|
   |---- list(next_cursor)（如仍有下一页） ---------->|
   |<--- 下一页，最多 50 项 -------------------------|
   |---- ping --------------------------------------->|
   |<--- pong；TLS/TCP 连接仍保持 --------------------|
   |---- quit --------------------------------------->|
   |<--- bye；双方关闭 TLS/TCP -----------------------|
```

### 3.4 上传时序

```text
图形客户端                                        服务端
   |---- upload(name, size, sha256) ---------------->|
   |<--- ready --------------------------------------|
   |==== 分块发送恰好 size 字节的载荷 ===============>|
   |                                      写入同目录临时文件
   |                                      计算 SHA-256
   |                                      校验后原子替换
   |<--- uploaded(name, size) -----------------------|
   | 界面显示完成状态并刷新文件列表                 |
```

客户端先计算本地文件 SHA-256，再发送文件名、字节数和摘要。服务端检查文件名、单文件上限及用户配额后才返回 `ready`。传输失败或摘要不符时，临时文件会被清理，不会覆盖原文件。

### 3.5 下载时序

```text
图形客户端                                        服务端
   |---- download(name) ---------------------------->|
   |<--- size、sha256 -------------------------------|
   |<=== 分块发送恰好 size 字节的载荷 ===============|
   | 写本地临时文件并逐块计算 SHA-256                |
   | 摘要匹配后原子替换所选本地目标                  |
   | 界面显示保存位置和校验结果                      |
```

## 4 图形界面设计

界面使用 Python Tkinter，无需额外 GUI 依赖。左侧填写服务器地址、用户名、密码及 CA/客户端证书路径；右侧显示远端文件列表，并提供刷新、上传、下载和长连接测试按钮。上传通过系统文件选择窗口选取本地文件；下载通过保存位置窗口指定目标路径。界面展示传输进度、连接状态和完整性校验结果。

登录成功后密码框清空。传输过程中相关操作按钮暂时停用，文件传输完成后自动刷新远端列表。双击远端文件也可开始下载。多用户演示可同时打开多个图形客户端窗口，各自使用不同账号登录。

## 5 安全设计与适用边界

| 风险 | 实现控制 | 适用边界 |
|---|---|---|
| 中间人窃听或篡改 | TLS 1.2+；客户端验证服务端 CA 链和主机名；服务端要求受信任的客户端证书；文件端到端 SHA-256 校验 | 演示 CA 仅用于课程演示；正式部署应使用可信 CA 并通过安全渠道分发客户端身份材料 |
| 暴力登录 | 随机盐和 PBKDF2-HMAC-SHA256；统一认证失败信息；每 IP 每分钟最多 5 次失败 | 不替代多因素认证或上游身份系统 |
| 并发与资源耗尽 | 并发连接上限 64、TCP backlog 128、Socket 空闲超时 90 秒、传输总时限、单文件 512 MiB、每用户 2 GiB、控制头 64 KiB | 限制应用层资源占用；大流量 DDoS 仍需防火墙、反向代理或云端清洗 |
| SQL 注入 | 不使用 SQL 数据库；账号信息存储在 JSON 文件中 | 本实现没有 SQL 查询面 |
| 路径穿越与跨用户访问 | 只接受单一文件名；拒绝路径分隔符、系统保留名和符号链接；每个账户绑定独立目录 | 生产部署还应以专用低权限系统账户运行服务 |
| 文件损坏或部分写入 | 精确分帧、SHA-256 校验、同目录临时文件、校验成功后原子替换 | TLS 提供通道保密和对端认证；SHA-256 检测传输后的内容不一致 |

演示 CA 私钥、服务端私钥、客户端私钥、账号数据库和用户文件均被 `.gitignore` 排除。Windows 部署可使用 `scripts/set_storage_acl.ps1` 将存储目录权限限制到服务账户、SYSTEM 和管理员。

## 6 Windows 运行方法

需要 Python 3.10 或更高版本、Tkinter 和 PowerShell 7（用于生成 Windows 演示证书）；Python 部分只使用标准库。详细步骤、界面操作和录屏顺序见同目录的《使用与录屏指南.md》。本机演示时默认连接地址为 `127.0.0.1:9443`，证书默认从 `certs/mtls/` 读取。

```powershell
Set-Location D:\workspace\projects\python\hw\hw4\1B_secure_file_transfer
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\generate_demo_cert.ps1
py server.py add-user demo_user
py server.py serve --host 0.0.0.0 --port 9443
```

另开终端后运行 `py client_gui.py` 启动图形客户端。输入创建的账号密码，选择证书目录中的 `ca-cert.pem`、`client-cert.pem` 和 `client-key.pem`，登录后即可上传或下载文件。

## 9 结论

本项目以长度前缀 JSON 控制帧和定长二进制载荷构成应用层协议，以 Tkinter 提供可选文件上传和下载界面。双向 TLS、账号认证、并发限制、配额、目录隔离、精确传输和摘要校验共同满足实验 1B 的主要要求。正式互联网部署仍应配置可信证书、系统 ACL 和上游 DDoS 防护。
