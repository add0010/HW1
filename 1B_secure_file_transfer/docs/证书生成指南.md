## 原有脚本无法运行的原因

### 问题1: OpenSSL 路径硬编码
所有旧脚本都写死了:
```
D:\software\git\Git\usr\bin\openssl.exe
```

如果你的Git安装在其他位置(如 `C:\Program Files\Git`),脚本就会失败。

### 问题2: PowerShell 版本要求
`generate_demo_cert.ps1` 需要 PowerShell 7,但Windows 11默认是PowerShell 5.1:
```powershell
# 脚本第2行检查
if ($PSVersionTable.PSVersion.Major -lt 7) {
    throw "Run this Windows certificate script with PowerShell 7..."
}
```

### 问题3: 相对路径问题
脚本使用相对路径 `..\certs\mtls`,如果不在正确目录执行会失败。

## 手动指定OpenSSL路径

如果自动检测失败,脚本会提示你手动输入OpenSSL路径。

### 查找OpenSSL位置

#### 如果安装了Git for Windows:
```
C:\Program Files\Git\usr\bin\openssl.exe
C:\Program Files (x86)\Git\usr\bin\openssl.exe
```

#### 如果单独安装了OpenSSL:
```
C:\Program Files\OpenSSL-Win64\bin\openssl.exe
C:\OpenSSL-Win64\bin\openssl.exe
```

#### 在PowerShell中查找:
```powershell
Get-Command openssl -ErrorAction SilentlyContinue
```

#### 在CMD中查找:
```cmd
where openssl
```

## 生成的证书文件

成功后会在 `certs\mtls\` 目录生成以下文件:

```
ca-cert.pem       # CA根证书 (服务器和客户端都需要)
ca-key.pem        # CA私钥 (签发证书用,生产环境需保密)
server-cert.pem   # 服务器证书
server-key.pem    # 服务器私钥
client-cert.pem   # 客户端证书
client-key.pem    # 客户端私钥
```

## 故障排除

### 问题: "找不到 OpenSSL"

**解决方案1**: 安装 Git for Windows (推荐)
1. 下载: https://git-scm.com/download/win
2. 安装时选择默认选项
3. Git会自动包含OpenSSL

**解决方案2**: 单独安装 OpenSSL
1. 下载: https://slproweb.com/products/Win32OpenSSL.html
2. 选择 "Win64 OpenSSL v3.x.x" 完整版
3. 添加到系统PATH

### 问题: "证书已存在"

删除旧证书:
```powershell
Remove-Item certs\mtls\*.pem
```

或让脚本提示时选择 `y` 覆盖。

### 问题: PowerShell脚本执行被阻止

临时允许执行:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\generate_certs_auto.ps1
```

或永久设置(管理员权限):
```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

### 问题: "无法识别的参数"

确保OpenSSL版本 >= 1.1.1:
```cmd
openssl version
```

如果版本太旧,更新Git for Windows或OpenSSL。

## 验证证书

生成后可验证证书:

```bash
# 查看CA证书
openssl x509 -in certs/mtls/ca-cert.pem -noout -text

# 查看服务器证书
openssl x509 -in certs/mtls/server-cert.pem -noout -text

# 验证证书链
openssl verify -CAfile certs/mtls/ca-cert.pem certs/mtls/server-cert.pem
openssl verify -CAfile certs/mtls/ca-cert.pem certs/mtls/client-cert.pem
```

## 安全提醒

⚠️ **私钥保护**
- `*-key.pem` 文件包含私钥,不要分享或提交到Git
- `.gitignore` 已配置忽略这些文件

⚠️ **证书用途**
- 这些证书**仅用于开发测试**
- 生产环境请使用正规CA签发的证书

⚠️ **有效期**
- CA证书: 10年
- 服务器/客户端证书: 1年
- 过期后需重新生成

## 常见问题

**Q: 为什么需要双向TLS?**  
A: 不仅服务器需要证明身份,客户端也需要证明身份,提供更高的安全性。

**Q: 可以用自签名证书吗?**  
A: 可以,这就是自签名CA。生产环境建议用Let's Encrypt等免费CA。

**Q: 多个客户端需要不同证书吗?**  
A: 安全起见,建议每个客户端使用独立证书。可以修改脚本生成更多客户端证书。

**Q: 证书过期了怎么办?**  
A: 删除旧证书重新运行脚本即可。服务器和客户端需要重启。
